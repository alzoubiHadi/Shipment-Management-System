Harden and improve reports without changing report architecture

Backend (ReportController.php, routes/api.php):

1. Permission gate: /reports/drivers, /reports/companies, and /reports/summary
   used to sit behind nothing but auth:sanctum -- any authenticated driver or
   company could pull every driver/company report and the commission summary
   straight from the API. Added a requireAdmin() check (Super Admin or Sub
   Admin only) to all three.

2. Driver self-report IDOR: the old /driver/{driver_user_id}/report endpoint
   trusted the id in the URL with no ownership check, so any authenticated
   user could read another driver's balance, earnings, and pending amount by
   editing the URL. Added a new /my-driver-report endpoint that resolves the
   driver from the authenticated user (no id at all), and added an ownership
   check (self or admin) to the old route, kept for backward compatibility.
   Flutter's ReportService now calls /my-driver-report.

3. pending_amount bug: the query required status=3 AND
   delivery_status=awaiting_confirmation, a combination that never actually
   occurs in this state machine -- status only ever becomes 3 in the exact
   same update() call that sets delivery_status=confirmed (see
   ShipmentController::confirmDelivery()/resolveDispute()). pending_amount
   was therefore always 0. Fixed to key off delivery_status alone. Also added
   disputed_amount (delivery_status=disputed) so a driver isn't left
   wondering where a disputed shipment's earnings went.

4. Commission correctness: summary() now also requires
   delivery_status=confirmed (redundant against today's state machine, but
   cheap defense-in-depth so a disputed shipment could never silently count
   toward realized commission even if a future code path changes). Sum moved
   from a PHP Collection::sum() over a full ->get() to a SQL SUM().

5. N+1 fixes: drivers() used to run 2 extra count() queries per driver
   in a loop; companies() used to fetch every shipment row per company and
   group in PHP. Both replaced with grouped aggregate queries (2 total for
   drivers(), 2 total for companies()) -- response JSON shape is unchanged,
   only the query count no longer scales with driver/company count.

6. Added ?period=month|30d|all to summary/drivers/companies (default: all,
   no filter), applied against shipments.created_at.

7. summary() now also returns a status_overview breakdown
   (delivered/active/cancelled counts) for the new dashboard chart, and a
   currency field.

8. New tests in ShipmentBusinessRulesTest.php: admin-only enforcement on all
   three report endpoints, the driver-self IDOR fix (own report works,
   another driver's 403s, admin can view any), /my-driver-report returns own
   data, and regression tests for the pending_amount/disputed_amount fix.
   Fixed the pre-existing commission test to act as an admin and set
   delivery_status=confirmed on its fixtures (previously relied on the
   now-closed permission hole and an incomplete fixture).

Flutter:

- ReportService.dart: fetchMyDriverReport() now calls /my-driver-report
  instead of building /driver/$userId/report from local storage.
  fetchDriverReports()/fetchCompanyReports()/fetchSummaryReport() gained an
  optional period parameter (default 'all', so existing call sites are
  unaffected).
- DriverReportsPage.dart: driver cards now show rating, a compliance-status
  badge, and a Success Rate bar (completed / (completed + cancelled)) --
  computed client-side from fields the backend already returned but the UI
  never rendered. No backend change needed for this part.
- CompanyReportsPage.dart: company cards now show a Completion Rate bar
  (Delivered / total_shipments), same no-backend-change approach.
- ReportsHomePage.dart: added a 30 Days / This Month / All Time period
  filter wired to the new query param, AED-formatted commission (no `intl`
  dependency -- a small local thousands-separator formatter), and a
  "Shipments Overview" bar chart (Delivered/Active/Cancelled) using the new
  fl_chart dependency and the summary endpoint's status_overview field.
- DriverBalancePage.dart: shows a Disputed Amount stat when non-zero.
- pubspec.yaml: added fl_chart for the new chart widget.

Scope note: deliberately did not touch the report screens' overall
structure (Dashboard -> Driver/Company Reports + Summary stays as-is),
did not move commission calculation onto the Ledger, and did not add PDF/
Excel export, custom date ranges, or any new database tables -- all
explicitly out of scope per the reports review this is based on.
